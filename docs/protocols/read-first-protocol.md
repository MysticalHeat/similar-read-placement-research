# Двухэтапная диагностика Read раньше Write

Фиксированный порог: 90% ошибок меньше следующей перезаписи. Старый общий критерий оценивается на всех прежних завершённых примерах без исключений. Дополнительно изучаем выборочное применение: точность класса Read-first, доля проходящих внутри выбранной группы, покрытие и MAE. Эти показатели не заменяют общий критерий.

Все дни уже просмотрены: день 5 — обучение, день 6 — выбор, день 7 — повторная диагностика после фиксации. Только точный начальный Offset, порядок исходных строк; физические диапазоны и время завершения I/O не моделируются. Незавершённые Write не входят в сохранённую обучающую выборку; coverage исходных Write публикуется.

Причинные признаки предыдущего overwrite90 дополняются последним известным исходом Read-first, средней долей Read-first последних пяти завершённых пар и числом известных исходов. **История исходов обновляется только после Read**, даже если Write-first можно было узнать раньше. Это исключает зависимость от будущего попадания пары в сохранённую выборку завершённых интервалов. История исходов доступна лишь начиная с дня 5; ранние признаки задержек прогреваются днями 2–4. Будущая перезапись не является входным признаком.

Два классификатора LightGBM binary: 15/31 leaves, максимум 80 деревьев, min_child_samples=200, learning_rate=.1, reg_lambda=1, seed=42, deterministic, два потока. Early stopping 12 итераций по binary_logloss дня 6. Два условных регрессора raw-L1/log-L1: 31 leaves, максимум 80 деревьев, обучение только на Read-first дня 5, early stopping по MAE Read-first дня 6. Current включён как baseline времени. Порог вероятности из .5/.7/.8/.9/.95/.99.

На дне 6 выбирается комбинация classifier/time/threshold. Для диагностического выборочного режима нужны precision Read-first >=90%, нижняя граница error<overwrite >=90% и coverage не менее 10% оценённой выборки; из проходящих выбирается максимальное покрытие, затем минимальная MAE. 10% — ограничение поиска, а не согласованное пользователем допустимое покрытие. Если ни одна комбинация не проходит, выбирается максимальный минимум двух долей, затем coverage и MAE. Ничего не подбирается на дне 7.

Обе выбранные модели refit на днях 5–6 с фиксированными best_iteration. Порог не меняется после refit. Для остальных записей общий routed-прогноз использует current, поэтому знаменатель общего критерия сохраняется. Для validation следующая Write после 144h неизвестна; для финальной диагностики используются прежние EOF-аннотации. Сохраняются все validation-прогнозы, модели, hashes, выбор и независимый пересчёт; проверяются причинность и нулевые интервалы.
