# Суточный follow-up: протокол до запуска

Дата: 2026-10-04. Пользователь согласовал увеличение временного покрытия после первого пилота.

- Для каждого из usr_1 и prxy_1: первые **24 часа** от первого события, интервал `[t0, t0 + 24h)`. Максимум **40 000 000 событий** на нагрузку; если суточное окно не достигнуто, STOP с сохранением префикса, без объявления его суточным результатом.
- Те же адреса, признаки, target, baseline и параметры LightGBM, что в пилоте. Без подбора параметров, early stopping или выбора лучших временных окон. Две нагрузки обрабатываются последовательно; модель использует два CPU-потока.
- 60/20/20 по длительности фактически загруженного наблюдения; последнее событие может быть немного раньше ровно 24h. Разметка не пересекает границы splits, цензурированные записи исключены из регрессии/метрик и публикуются отдельно.
- Подготовка: потоковая запись компактных событий на диск, стабильная группировка по начальному Offset и векторное вычисление истории/next reads, features через mmap. Вспомогательные кэши удаляются после успешного результата, архивы не распаковываются полностью.
- Сохраняются результаты каждой нагрузки, модели, полные validation/test прогнозы в NPZ, метрики, coverage, baseline support, версии, hashes кода и прочитанного префикса, elapsed и RSS. Старый пилот сохранён отдельно.
- Семантика нового пути проверяется на ручных, случайных и граничных историях сравнением с исходным pipeline. Сохранённые прогнозы проверяются отдельным пересчётом ошибок и границ.
- Вывод ограничен двумя суточными префиксами и записями с наблюдаемым следующим чтением. Изменение coverage/периода может изменить MAE само по себе; процент улучшения сравнивается с baseline **внутри того же тестового окна**, а не интерпретируется как прямое улучшение относительно пилота.
