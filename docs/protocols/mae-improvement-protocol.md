# Улучшение MAE без изменения target — 2026-10-06

Протокол фиксируется до новых fits и просмотра labels после 96 часов.

## Постановка и разделение данных

- Сохраняем Write → первый последующий Read с тем же начальным Offset; промежуточные перезаписи не отменяют target. Единица — секунды. Блочная гранулярность и overwrite-критерий здесь не меняются.
- Обучение и early stopping используют прежние train/validation cutoffs первых суток. Training labels завершаются до train cutoff; validation labels — до validation cutoff. Validation используется для early stopping, не для fit.
- Уже опубликованные дни 2–4 становятся development, НЕ новым независимым тестом. Победитель отдельно для каждой нагрузки минимизирует pooled MAE: сумма абсолютных ошибок / число завершённых примеров этих трёх дней. Все дневные результаты, coverage и отрицательные исходы публикуются.
- Новый holdout: дни 5–7, окна [96h,120h), [120h,144h), [144h,168h). Последний день может быть частичным при EOF; граница и coverage публикуются. Нужны данные после 144h, иначе STOP. Никакого выбора, новых fits или перенастройки после holdout.
- Во всех окнах чтение должно завершиться до конца окна. Сравниваем методы на идентичных примерах. Вывод относится только к завершённым интервалам.

## Ограниченный поиск

1. Ровно восемь рецептов на нагрузку: log-L2 / log-L1 × все 7 признаков / без двух накопленных счётчиков × balanced / regularized. Balanced: 31 leaf, min_child_samples=50; regularized: 15 leaves, min_child_samples=200. learning_rate=0.05, reg_lambda=1, seed=42, два потока, deterministic. Максимум 1000 деревьев; early stopping после 50 итераций без улучшения MAE секунд. Автоматическая log-L2 metric отключается (`metric="None"`); единственная eval metric — MAE после expm1 и неотрицательного clipping.
2. Сохраняем только best_iteration дерева и проверяем равенство прогнозов после загрузки. Текущая замороженная модель и прежняя train-only адресная медиана включены в сравнение.
3. Для каждого модельного кандидата, включая текущую модель, проверяем model_weight 0.25, 0.5, 0.75 в смеси с адресной медианой. Чистые модели и чистая медиана — endpoints. Вес выбирается только на development.
4. Если первый раунд не улучшает pooled development MAE минимум на 5% относительно лучшего из current/address_median, выполняем дополнительный раунд: четыре рецепта log-L2/log-L1 × all/no-counts с лучшим development-профилем из первого раунда и четырьмя дополнительными признаками. Это условие — ограничение поиска, не обещание улучшения.
5. Дополнительные признаки: log1p последней завершённой write→read задержки, log1p медианы последних максимум пяти завершённых задержек по адресу, sin/cos времени суток (UTC FILETIME, период 24h). Для текущего Write используются только интервалы, чей Read строго раньше текущего события по порядку строк. Нет статистик по полной обучающей выборке, содержащих собственный/будущий target. NaN означает отсутствие завершённой истории.

## Исполнение и проверка

Сначала select usr_1, затем select prxy_1; обе selection и frozen.json создаются ДО holdout любой нагрузки. Отдельные новые артефакты в results/mae-improvement/. Максимум 200 млн событий на 168h; event-cap означает STOP, а не частичную оценку. Нагрузки и fits выполняются последовательно. Disk-backed events/features и пакетный inference; кэши сохраняются между select/evaluate и удаляются после успешной проверки этапа.

Сохраняем параметры, best_iteration, validation/development прогнозы и пять метрик, source/model/code hashes, coverage, round-one результаты и правило дополнительного раунда. Для holdout — только current/address_median/frozen selected, zero fits. Проверяем метрики независимо из прогнозов, минимум development MAE, выпуклые смеси, временные границы, hashes и сохранение модели. Дополнительные признаки тестируются на изменение будущего и отсутствие собственной метки. Holdout labels не участвуют в ранней остановке/выборе. Результат не доказывает пригодность группировки по времени чтения относительно перезаписи: это отдельная проверка.
