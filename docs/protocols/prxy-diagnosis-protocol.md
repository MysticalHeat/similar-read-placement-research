# prxy_1: диагностика до запуска

Пользователь разрешил выяснить причину проигрыша модели по обучению и validation. Test суточного запуска уже просмотрен; не использовать его для настройки или выбора нового варианта.

1. Восстановить только первые 20 133 864 строки, до конца validation. Сопоставить validation labels и прогноз исходной модели с сохранённым запуском, параметры и границы сохранить.
2. Показать train/validation распределения признаков и targets, выход счётчиков за обучающий диапазон того же адреса, ошибки по заранее выбранным корзинам времени с предыдущего чтения: 0–5, 5–15, 15–30, 30–60, 60–120, ≥120 секунд, отсутствие истории.
3. Ограниченные абляции 2×2: все признаки / без накопленных счётчиков чтений и записей; squared error на log1p интервале / L1 на интервале в секундах. Исходный вариант уже обучен, поэтому **ровно три новых fit**, по 150 деревьев, прежние остальные параметры, 2 CPU-потока, без early stopping/подбора.
4. Дополнительная эвристика без обучения: max(последний завершённый read→read интервал − время с предыдущего чтения, 0), при отсутствии истории — общая обучающая медиана.
5. Выбор по MAE в секундах на validation среди исходной модели, кандидатов, обеих медиан и исторической эвристики. Отрицательные результаты сохранять. Преимущество на validation — основание выбрать кандидата, не независимое доказательство качества на будущем test.
6. Сохранить прогнозы validation, параметры, метрики, распределения, модели и hashes кода. Отдельно проверить пересчёт метрик и выбор победителя. Для независимой будущей проверки нужен новый заранее выбранный временной участок.
