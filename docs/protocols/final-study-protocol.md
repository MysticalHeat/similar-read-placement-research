# Итоговый ограниченный протокол: usr_1 и prxy_1

Пользователь просит довести задачу предсказания до завершённого эмпирического этапа. Фиксируем объём до следующих запусков.

## Постановка

Для каждого Write прогнозировать `next_Read_timestamp − Write_timestamp` в секундах для того же **начального Offset в байтах** на одном logical volume. История только до записи; одинаковые timestamps обрабатываются в порядке исходных строк. Перезапись не отменяет пример: прогноз касается обращения к адресу, не потребления версии данных. Это выбранное упрощение относительно предсказания каждого покрытого блока.

## Выбор и будущие периоды

- prxy_1: уже выбранная по первому validation модель `no_counts_log_l2`; сохранить её и параметры. Вторые сутки ранее оценены и дают положительное свидетельство; теперь дни 3–4 являются дополнительными будущими периодами, день 2 воспроизводится для контроля.
- usr_1: выбор только на прежнем day-one validation по минимальной MAE секунд среди исходной модели, трёх фиксированных абляций (all/no-counts × log-L2/raw-L1, оригинал уже обучен), двух медиан и read-period эвристики. Ровно три новых fit, те же 150 деревьев/остальные параметры. Если baseline побеждает, не принуждать победу ML.
- Обе выбранные модели и baseline фиксируются; никакого переобучения или выбора модели по дням 2–4. История признаков обновляется из событий. Первая обучающая часть и cutoffs ровно те же, что в исходном суточном эксперименте.
- Проверочные дни: `[24h,48h)`, `[48h,72h)`, `[72h,96h)` от первого события каждой трассы. Все три результата публикуются, включая отрицательные. Не выбирать лучшую дату по качеству.
- Чтение должно произойти до конца соответствующего дня; остальные записи right-censored и исключены из регрессии/оценки, coverage публикуется. Будущие чтения вне обучения не используются для fit baseline или selection.

## Исполнение и проверка

Последовательно по workload: потоковый 96h prefix, cap 130 млн событий, STOP если 96h не достигнут. Компактные события на диске и mmap features, не полная распаковка. Два потока inference; вычислительная сортировка требует нескольких GiB памяти (проверено доступно около 12,8 GiB перед подготовкой). Кэши удаляются только после успеха. Артефакты сохраняются в `results/final-study/`; старые этапы сохранены.

Сохранить все validation/future predictions, выбор, модели, baseline, code/model/source hashes, coverage, пять метрик и runtime/RSS. До новых labels сохранить `frozen.json`. Отдельно перепроверить метрики из прогнозов, границы дней, выбор usr по validation и sample source histories. Никаких новых fits после просмотра будущих дней.

## Финальный deliverable

Единый отчёт RU/EN, таблица дней по двум workload, описание воспроизведения и notebook итогов. Основной критерий — MAE секунд относительно замороженной медианы адреса; дополнительно median AE, P90 AE, RMSE, log-MAE. Не объединять разные workload в одну безразмерную "accuracy". Не делать выводов о всех цензурированных записях, всей неделе, независимых популяциях, отдельных data versions или скорости SSD. Статистическую независимость дней не предполагать.
