# Дополнение диагностики: одинаковый горизонт наблюдения

После основных срезов, без переобучения и без изменения результатов, проверяем
эффект разных длин окон. Validation длится 4.8h, train 14.4h, future day 24h:
их observed labels имеют разные ограничения по доступному времени чтения.
Разницу распределений нельзя автоматически объявлять временным drift.

Новый каталог `results/new-workloads-horizon/`. Train разбиваем на три 4.8h
окна, каждый будущий день 2–7 — на пять 4.8h окон от того же origin.
Только Write/первое Read внутри одного малого окна; перезапись тоже обрезается
его концом. Validation сохраняется без изменений (одно 4.8h окно).
Same-start/range правила прежние; модели/медианы не меняем. Ничего не исключаем
из основной оценки: публикуем дополнительный срез с меньшим покрытием.

Сравниваем target distributions и future model/median MAE/pass/bias. Этот
контроль ограничивает влияние различного горизонта, но также меняет набор
строк и не является доказательством отсутствия/наличия причинного drift.
Проверяем все retained target <4.8h, N <= original observed N, bounds и
совпадение исходной validation. Протокол до controlled-horizon метрик.
