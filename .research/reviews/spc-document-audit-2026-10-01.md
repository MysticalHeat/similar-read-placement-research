## Summary and exact support eligible for integration
S018/C022 now has direct local extracted-primary-text support for a GENERIC format, replacing the earlier search-only lead for those propositions alone. Extraction success and resource compliance are separate claims.
Suggested bounded claim: “The saved SPC TRACE FILE FORMAT SPECIFICATION, cover revision 1.0.1, specifies comma-separated, newline-terminated I/O-command records with five required fields in order ASU, LBA, Size, Opcode, Timestamp, and optional trailing fields (§§1.1–1.2.6).” Support: extracted.txt:L75–151.
ASU means application specific unit; LBA is its zero-based block offset, with block size supplied by the particular trace description (§§1.2.1–1.2.2, L91–105). This does NOT establish a physical volume or 512-byte LBA units.
Size is bytes; zero is explicitly legal and 512-byte multiples are not mandatory (§1.2.3, L107–113). R/r means read from ASU to host, W/w write to ASU (§1.2.4, L115–125); this defines tokens, not READ presence in a named file.
Timestamp is a nondecreasing seconds offset from trace start, with integer and fractional parts; the first event need not be 0.0 (§1.2.5, L127–133). Exact issue-versus-completion capture semantics are not specified by that field definition.
Use section/line locators: printed pagination differs from extraction page order. Cover L1–15 gives title, SPC credit, revision and copyright, not an independently established issue date; history L33–37 separately writes version 1.01. Do not silently harmonize these notations.
