## 1. Неизменные потолки и граница workload
- TOTAL: active wall≤120s; aggregate CPU≤120s; RAM всего workload-domain≤1073741824 bytes (1GiB); один активный Python worker/один thread, no research children; new disk≤5242880 bytes (5MiB). No network/install/paid/GPU/remote.
- Domain включает worker, все research launcher/watchdog/wrappers/observers и их startup, termination, cleanup; не только функцию generator/fit. E004 и E005 — последовательные отдельные worker invocations, не одновременно живущие процессы.
- Дополнительный research supervisor НЕ разрешён автоматически: указать launcher/watchdog и process/thread counts явно. Если нужен дополнительный research process или exact all-process limit=1 недостижим, gate UNKNOWN→STOP; изменение требует human-approved amendment, не тихого повышения pids/бюджета.
- Shared-host tool server, systemd manager и kernel не объявляются whole-machine RAM domain. Это не лазейка: все research wrappers должны быть contained до startup; любые отдельно разрешённые control commands учитываются по CPU/wall/disk, их process/RAM scope тоже предъявляется до approval. Unmeasured sideload запрещён.

## 2. Общий ledger, не новый бюджет на каждый запуск
- Один накопительный ledger: bootstrap/inventory + E004 + E005 + repeated startup/checks + cleanup/final writes + failed attempts + вся разрешённая control/observer работа. Ни stage, ни повторный старт не получают новые 120s/120CPU-s.
- Active wall = сумма непересекающихся monotonic intervals от начала каждой разрешённой активной операции до конца termination/accounting/cleanup; параллельный overhead внутри interval не удваивает wall. Aggregate CPU = сумма user+system CPU всех workload/control процессов, без двойного счёта общих cgroup counters.
- Ожидание человеческого G2 между stages исключено ТОЛЬКО после exit всех research processes и завершения accounting; worker/watchdog не остаётся живым. Активное ожидание, запуск/завершение и запись receipt учитываются.
- Сохраняются cumulative wall/CPU subcaps (s): inventory/startup/limit checks 15/15; E004 generator/fixtures/features 35/35; E005 четыре fits 40/40, каждый≤10/10; prediction/metrics 15/15; final manifests/checksums/cleanup 15/15. Bootstrap расходует первый subcap, не добавляется сверху; repeated startup тоже из него. TOTAL имеет приоритет.
- До операции резервируются оставшиеся wall/CPU/disk для termination и failure receipt; если резерва нет — STOP до работы. Failed attempts расходуют ledger; нет auto-retry/extension/regeneration или нового fit ради качества.
- Будущий ledger row: phase/stage/attempt, authorization reference, operation/process scope, interval start/end + clock/observer, CPU counter source/baseline/delta, RAM observations/limit/events, disk logical/allocated/reserves, exit/status/reason, cumulative totals/remaining. Где/кем измерять — пока UNKNOWN, не фиктивные значения.

## 3. Containment и полнота accounting — блокирующие gates
- Preferred proposal: свежий dedicated cgroup v2, проверенная delegation/permissions, memory.max=1073741824 и memory.swap.max=0 ДО первого fork/startup research process; весь workload contained с начала до termination. Existence cgroup ≠ право создать/настроить/использовать его.
- Нужны phase-identified resource-control receipt, effective settings, containment membership, code/config version+hashes; proposal не является runtime receipt. Exact launcher, environment, CPU/wall stop mechanism, observation cadence и bounded termination reserve — UNKNOWN, заморозить до исполнения.
- Сохранять startup-through-termination memory.current/peak, cpu.stat, memory events и wall observations; для каждого stage — start baseline, phase attribution, end/exit accounting, final snapshot после empty domain ДО удаления cgroup. RAM относится к согласованному cgroup charge, не заявлению о RAM всей машины.
- Worker pre-exit manifest недостаточен: post-exit observer/parent-cleanup должен включить worker exit и final cgroup snapshot; его собственные final writes, CPU, wall и exit тоже входят в ledger. Кто завершает этот учёт без запрещённого extra process/unmeasured tail — UNKNOWN; невозможность полного bounded охвата означает STOP, не «complete».
- При будущем новом raw stage accounting receipts добавляются как новые uniquely named artifacts, без overwrite предварительного manifest/receipt; сохраняются control configuration, observations, exit/failure и ledger links. Сейчас raw directories не создаются.
- Не применять AS-limit arithmetic, ru_maxrss или pre-exec предположение как whole-domain RAM proof. Timeout/OOM/crash/cap/неполные observations → failed/incomplete receipt + STOP, без сравнительного F1 для incomplete models; compliance при missing tail не утверждается.

## 4. Disk: два измерения, один фиксированный потолок для каждого

- Scope: ВСЕ новые demo artifacts с начала принятой code preparation: code/modules/config/tests, этот contract/control notes, fixtures, bootstrap receipts, raw E004/E005, processed, logs/manifests/checksums, failed/partials. Позднее перемещение вне budget path не исключает artifact из ledger.
- Existing pre-CODEPREP artifacts/raw исключены только как фиксированный unchanged baseline; prepared demo files нельзя объявлять baseline. Exact baseline/path inventory/namespace collection, file-count bound, allocation unit/metadata reservation и текущий расход UNKNOWN; их нужно зафиксировать, не измерено сейчас.
