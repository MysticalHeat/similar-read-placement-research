# proj_1 и prn_1: первые замороженные будущие оценки

**Данных для обучения хватило, но 90% не достигнуты ни на одной нагрузке.**
Скрининг показал достаточность первого train/validation до просмотра будущих
метрик. Обучение и выбор — только первый день, будущая оценка — все дни 2–7.
Это первые будущие оценки этих нагрузок в данной серии, не новый источник вне MSR.

## Что обучили

Для каждого workload и каждого правила label: два фиксированных LightGBM
log-L2 (все семь past-only признаков / без накопленных счётчиков) плюс две
training-only медианы. Train 0–14,4h, validation 14,4–19,2h, labels не
пересекают границы. Выбор по максимальной validation lower pass, tie-break MAE.
Дополнительно фиксировался MAE-best метод. Во всех четырёх постановках оба
правила выбора выбрали **all_features**. Будущая настройка не выполнялась.

| Нагрузка / label | Train labels | Validation labels | Validation pass lower | Validation MAE, с |
|---|---:|---:|---:|---:|
| proj_1 / same-start | 182 142 | 21 556 | 66,86% | 4 440,74 |
| proj_1 / range | 219 900 | 26 664 | 62,33% | 4 427,00 |
| prn_1 / same-start | 75 329 | 11 833 | 34,57% | 3 646,65 |
| prn_1 / range | 82 136 | 16 739 | 28,46% | 4 113,63 |

Labels и исходный cache первого дня точно совпали с предыдущим скринингом.
Полные загруженные источники: proj_1 — 23 639 742 событий (2 496 935 Write),
prn_1 — 11 233 411 событий (2 769 610 Write), до EOF в пределах первых 168h.

## Основной критерий на будущих днях 2–7

Строго `abs(predicted_read_delay - actual_read_delay) < next_overwrite_delay`.
Знаменатель — **все Write с наблюдаемым последующим Read внутри своего дня**,
не только Read-first и не выбранный gate набор. Перезаписи между Write и Read
не отменяют label. При неизвестной следующей Write публикуются lower/upper
bounds; неизвестные не превращены в failures.

| Нагрузка / label | Все Write | Наблюдаемый N / coverage | Модель: pass lower–upper | Адресная медиана: pass lower–upper | Изменение lower |
|---|---:|---:|---:|---:|---:|
| proj_1 / same-start | 1 699 664 | 341 598 / 20,10% | **56,69–56,74%** | 54,95–55,07% | +1,73 п.п. |
| proj_1 / range | 1 699 664 | 380 787 / 22,40% | **52,53–52,61%** | 49,93–50,06% | +2,60 п.п. |
| prn_1 / same-start | 2 364 691 | 1 109 941 / 46,94% | **55,15–55,16%** | 49,69–49,75% | +5,46 п.п. |
| prn_1 / range | 2 364 691 | 1 181 952 / 49,98% | **50,75–50,75%** | 45,84–45,93% | +4,90 п.п. |

Модель улучшила долю проходов относительно адресной медианы **на тех же строках**,
но не достигла 90%. Coverage не является точностью: качество неизвестно для
Write без наблюдаемого Read. Нет результата «90% на всех Write».

## Ошибка времени: выбранная модель против адресной медианы

| Нагрузка / label | Модель MAE, с | Медиана MAE, с | Модель P90, с | Медиана P90, с |
|---|---:|---:|---:|---:|
| proj_1 / same-start | 14 144,60 | **12 430,66** | 35 570,29 | **26 148,27** |
| proj_1 / range | 12 360,22 | **11 651,10** | 32 884,74 | **26 842,91** |
| prn_1 / same-start | 19 006,74 | **14 543,66** | 46 870,72 | **37 411,10** |
| prn_1 / range | 18 530,90 | **14 131,15** | 46 471,58 | **37 007,20** |

Здесь выбранные модели хуже по MAE и P90. Показатель «error < overwrite» и
качество времени не эквивалентны. Кандидат no_counts даёт pooled MAE 13 021,21 /
11 498,46 с для proj_1 и 18 272,42 / 17 873,68 с для prn_1 (same-start / range).
Для proj_1 range это немного лучше адресной медианы, но кандидат **не выбран**
на validation; будущий результат нельзя использовать для незаявленной замены.
Все четыре метода сохранены в `metrics.json`.

## Диапазонные исходы всех Write дней 2–7

| Нагрузка | Read-first | Write-first | Unresolved до конца дня |
|---|---:|---:|---:|
| proj_1 | 249 208 (14,66%) | 650 557 (38,28%) | 799 899 (47,06%) |
| prn_1 | 691 748 (29,25%) | 1 131 478 (47,85%) | 541 465 (22,90%) |

Перезаписи здесь заметно реже, чем у prxy_0 (99,27%), но 90% всё равно нет.
**Объяснение только частыми перезаписями недостаточно.** Данные для обучения
есть, однако текущие признаки/фиксированные модели не дают нужной будущей
точности. Возможные направления: более длинный training history, режимы
нагрузки и признаки интенсивности I/O; этот эксперимент их не проверял и
не доказывает причинную роль какого-либо одного фактора. Unresolved не равно
«никогда не читают»; любое пересечение не равно полной перезаписи версии.

## Проверки и воспроизведение

Для двух нагрузок проверены 3 072 Write прямым линейным поиском первых
Read/Write. Независимый checker проверил 28 окон × 4 метода: метрики, bounds,
границы labels, frozen выбор, восстановленные model/baseline прогнозы,
pooled MAE/P90 и hashes. Features короткого префикса проверены независимым
forward pipeline. 82 unit-теста прошли.

Протокол: `docs/protocols/new-workloads-protocol.md`.
Результаты: `results/new-workloads/{proj_1,prn_1}/`.

```bash
.venv/bin/python -m read_prediction.experiments.new_workloads proj_1
.venv/bin/python -m read_prediction.experiments.new_workloads prn_1
.venv/bin/python -m read_prediction.checks.new_workloads proj_1
.venv/bin/python -m read_prediction.checks.new_workloads prn_1
```

Эксперимент не перезаписывает готовый каталог. Checker не обучает модели.
