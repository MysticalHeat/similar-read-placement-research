# Ошибка прогноза и следующая перезапись

Сравнение сохранённых прогнозов дней 5–7: никаких новых fits или изменений выбора моделей. Протокол — `../../docs/protocols/overwrite-comparison-protocol.md`, отчёт — `../../reports/overwrite-comparison.ru.md`.

В каждой папке нагрузки:

- `summary.json` — показатели по дням и pooled: совпадающая выборка с известной следующей Write, неизвестные интервалы, error < overwrite и Read раньше повторной Write;
- `day{5,6,7}.comparison.npz` — индексы следующих Write, интервалы, цензурирующие нижние пределы и порядок Read/Write; исходные прогнозы остаются в `../mae-improvement/`;
- `verification.json` — независимый пересчёт, hashes прежних прогнозов/моделей и новой программы;
- `censoring-bounds.json` — нижняя граница среднего и нижняя/верхняя границы медианного интервала для всей исходной выборки, включая неизвестные следующие Write.

Под перезаписью подразумевается следующий Write с тем же начальным Offset, а не физическое перекрытие блоков. Публикуемые доли относятся к уже оценённым записям с Read до конца дневного окна, а не ко всем Write. Поиск следующей Write допускает пересечение границы дня и заканчивается в EOF/168h. Отсутствующая Write не считается бесконечным измеренным интервалом.

Проверка и полный отчёт:

```bash
uv run python -m read_prediction.checks.overwrite_comparison --workload usr_1
uv run python -m read_prediction.checks.overwrite_comparison --workload prxy_1
uv run python -m read_prediction.overwrite_reporting
```

Среднее может быть очень большим за счёт долгоживущих адресов. Поэтому сравнение MAE со средним и с медианой интервала, а также доля пообъектных error < overwrite — разные критерии. Выполнение одного из них не доказывает правильную группировку без заданной ширины временных групп и учёта судьбы конкретной версии данных.
