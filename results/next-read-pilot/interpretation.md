# Интерпретация первого эксперимента

## Что проверено

Прогноз времени от записи до первого следующего чтения того же начального байтового адреса. Для каждой нагрузки прочитан первый миллион событий, модель обучена отдельно. Разделение 60/20/20 по длительности наблюдения; параметры фиксированы, настройки по validation или test нет.

| Нагрузка | Временное покрытие | Завершённые интервалы train / validation / test | Доля test-записей с наблюдаемым чтением |
|---|---:|---:|---:|
| usr_1 | 4,13 часа | 403 / 0 / 796 | 1,03% |
| prxy_1 | 55,12 минуты | 109 549 / 32 874 / 33 693 | 48,46% |

## Результат

| Нагрузка | Общая медиана: MAE, с | Медиана адреса: MAE, с | LightGBM: MAE, с |
|---|---:|---:|---:|
| usr_1 | 3107,18 | 3107,18 | 2587,33 |
| prxy_1 | 19,70 | 18,55 | 16,83 |

- **prxy_1:** MAE модели ниже baseline по адресу примерно на **9,3%**; медианная абсолютная ошибка также ниже: 6,95 против 11,83 секунды. Но P90 ошибки хуже: **56,20 против 46,42 секунды**, RMSE хуже: 28,44 против 25,38 секунды, MAE log1p хуже: 0,563 против 0,434. Поэтому модель не превосходит baseline по всем критериям. Обучающая MAE 1,36 секунды против тестовой 16,83 также показывает, что низкая ошибка на train не переносится на будущее.
- **usr_1:** MAE ниже baseline примерно на **16,7%**, но это всего 796 завершённых интервалов и около 1% test-записей. Обучение использует только 403 интервала, validation пустой. Baseline по адресу совпадает с общей медианой на test. Надёжность и пригодность такого прогноза пока не установлены.
- Это **условная оценка среди записей с чтением до конца окна**, а не оценка всех записей. Остальные интервалы неизвестны; они не объявлены бесконечными или никогда не читаемыми.

## Изменение протокола до обучения

Проверка 300 000 событий usr_1 с cuts по количеству событий дала 1 905 / 0 / 0 завершённых интервалов. Расширение до миллиона с такими же cuts дало 6 049 / 1 / 0. Оба запуска остановились до обучения. Из-за неравномерной интенсивности запросов окончательные cuts выбраны по длительности наблюдения, одинаково для обеих нагрузок. Это exploratory-решение по доступности разметки; качество моделей не использовалось для выбора cuts.

## Следующий содержательный эксперимент

Увеличить временное покрытие по заранее выбранному правилу, чтобы охватить смену фаз нагрузки и получить достаточно завершённых интервалов usr_1. Для больших фрагментов потребуется компактное или потоковое представление вместо списка Python-объектов. Затем рассмотреть отдельный прогноз «будет ли чтение в горизонте H» либо модель с цензурированием, и согласовать блочную гранулярность вместо точного начального Offset. До этого не делать выводов о полном workload, чтении версий данных или ускорении SSD.
