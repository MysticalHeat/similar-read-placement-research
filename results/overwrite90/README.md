# Порог 90%: причинный диагностический поиск

Протокол: `../../docs/protocols/overwrite90-protocol.md`. Отчёт: `../../reports/overwrite90.ru.md`.

Все дни ранее просмотрены. Обучение на дне 5, выбор на дне 6, фиксация рецепта перед повторной диагностикой дня 7. Нового независимого holdout нет. Порог применяется к нижней границе доли `ошибка < интервал до следующей Write`; нет отказов от прогнозов и отбрасывания нулевых интервалов. Оцениваются прежние завершённые примеры, не все Write трассы.

В папке каждой нагрузки:

- `selection.json` — 15 validation-рецептов, выбор, параметры и hashes;
- `validation.predictions.npz`, `validation-*.lightgbm.txt` — воспроизводимые validation-прогнозы и модели;
- `frozen.json` — hash выбора и, при наличии, выбранной refit-модели;
- `selected.lightgbm.txt` — модель после refit, если выбран модельный рецепт;
- `day7.predictions.npz`, `diagnostic.json` — прогнозы и сравнение с прежней моделью на тех же примерах;
- `verification.json` — независимые counts и выборочная реконструкция причинных прогнозов;
- `error-breakdown.json` — разбор ошибок по длительности перезаписи и порядку Read/Write.

Большие NPZ остаются внешними артефактами согласно общей политике проекта. Старые frozen-модели не изменяются. Отчёт: `uv run python -m read_prediction.overwrite90_reporting`.
